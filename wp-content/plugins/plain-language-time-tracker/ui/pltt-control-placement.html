Where the controls go

Two separate questions. The view toggle — settled, it moves next to the title. The date control — a genuine tradeoff between two defensible placements.

01

The view toggle

Navigation, not scoping.

Summary and Entries are two pages. The toggle changes which one you're on and survives every filter change — it's navigation. Grouping it with the date control implies it does the same kind of work, which it doesn't.

Why left

The toggle belongs to the page name — it's naming a subview of Entries, so it reads as a tab pair when it sits against the title. That's also the WordPress convention: subviews near the title, tools at the right margin.

The tradeoff

For: the date control is in exactly the same place on all seven screens, whether or not that screen filters. Nothing to hunt for. Filterless screens stay tight.

Against: the date is a filter — it narrows data exactly as the dropdowns do — and this separates it from them. On Entries you set scope in two places, one row apart.

The tradeoff

For: everything that narrows the data lives in one bar, labelled the same way. "Clear all" can then genuinely clear everything including the period. Conceptually tidier.

Against: filterless screens gain a bar holding one control, which is a lot of furniture for a date stepper — see Today above. And the bar's height varies by screen, so the page body starts at a different place depending on where you are.

Recommendation, weakly held

A. Today is the screen you open most, and giving it a filter bar containing a single date stepper is the wrong trade for a conceptual tidiness you'd notice once and then stop seeing. Consistent position beats consistent category.

The one thing that would flip it: if you find yourself reaching for the period control while already looking at the filter bar, and having to travel back up. That's a real cost and only using it will tell you.
