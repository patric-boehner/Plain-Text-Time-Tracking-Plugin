Row actions, unified

Four patterns are currently doing overlapping work: WP hover row actions, trailing links, buttons in cells, and the kebab menu I introduced. Three rules replace all of them — and the first removes most trailing links on its own.

02

Three rules

1

The row's name is the link

Navigation to the thing a row represents happens by clicking what identifies it — client name, project name, bill record number, date. Never a trailing "View" or "Open" column. If a row has no obvious identifier to link, that's a sign the columns are ordered wrong.

2

Actions live in one always-visible menu

A kebab in the last column, present on every row, opening edit / delete / contextual actions. Always visible rather than hover-revealed: no layout shift, works on touch, and you can see that actions exist without discovering them.

3

A button only when the action is the row's purpose

If you came to this screen in order to act on its rows, the action is a button. Billing's ready list qualifies — every row is there to be billed. The clients list doesn't; you go there to find a client.

The test for rule 3: "Would I open this screen in order to do this to a row?" Yes → button. No → menu.

It's deliberately narrow. A screen gets at most one button-per-row action, and everything else on that row still goes in the menu.

Why not keep WP hover actions

They're native, and that's the argument for them. Against: they're invisible until hover, so nothing tells you actions exist; they shift the row when they appear; and they don't work on touch at all. The kebab costs one narrow column and solves all three.

Delete stays inside the menu, below a divider, in red — the one place red is permitted, because deleting a client with history is genuinely destructive.

05

Menu contents

Same order everywhere.

Primary edit first and highlighted, then navigation, then contextual actions, then destructive below a divider. Consistent ordering means the first item is always the one you want most.

Conventions

Ellipsis means a dialog follows — Edit client… opens a modal, Archive project acts immediately. Destructive items sit below a divider in red and always confirm. Red appears nowhere else in the app.

If a menu would hold one item, don't build a menu — that item becomes a link in the row. If it would hold more than six, the row probably needs a detail page.
