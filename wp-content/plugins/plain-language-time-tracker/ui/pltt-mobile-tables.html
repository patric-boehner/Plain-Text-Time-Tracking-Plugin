Tables on a phone

Today every table keeps its desktop columns on a phone and scrolls sideways. On Entries that puts the ⋮ menu, the only way into the edit modal, off the right edge until you swipe the table across.

The proposal is one pattern for every table:

  1. Each row becomes a small block. Line 1 says what the row is (its link) with the ⋮ menu top-right, where your thumb finds it on every screen.
  2. The facts go underneath, with the figures right-aligned in mono as on desktop.
  3. The column headings go. Each cell has to say what it is on its own, so "33m" and "$50.00" stay bare, but a bare "1" or "0.68" gets a word next to it.
  4. A cell that only holds "—" disappears instead of printing a dash on its own line.

Each "after" frame below is built from the table's real markup and class names, restyled with CSS alone (the .m rules at the top of this file stand in for the 782px breakpoint). Desktop doesn't change. Where a table needs a small template change, its notes say so.

What goes where

A covered (billed) row keeps its blue tint and 3px left edge. The badge sits on line 3 instead of in its own column.

Template change

None. The cells already carry pltt-entry-desc-cell, pltt-time-cell, pltt-status-col, pltt-amount-col and pltt-rowmenu-col. The one catch is that the duration and amount cells share pltt-duration-cell, so the CSS tells them apart with :not(.pltt-amount-col).

Decided: on a phone, tags and the billable $ are display-only; both are edited through the ⋮ → Edit modal. On desktop they stay editable in place. In CSS that's pointer-events: none on the tag and billable cells inside the breakpoint, so the inline tag picker and the $ toggle never open on a phone.

What goes where

  • Line 1: the date (the link), the status badge beside it, then ⋮.
  • Line 2: the log preview, cut to one line.
  • Line 3: "2 entries · 1h 32m".

Why line 3 needs its own text

Entries and Hours are bare numbers today ("2", "1.53"), which only make sense under their headings. With the headings gone they're merged into one phrase, and hours are shown as 1h 32m to match the week header above them instead of a decimal.

Template change

One extra cell carrying that phrase, hidden on desktop. The alternative is data-label attributes, which print "Entries 2 · Hours 1.53": it works, but it reads like a form.

One line of facts under the name

  • Clients: "$100.00/hr (default) · 4 projects". The bare project count gets its noun.
  • Projects: the type badge stays on line 1 beside the name, because it's the first thing you scan for. Client, rate, billable and (when there is one) budget fold into one line under it.
  • Tags: already narrow, so it stays one line: name, count, ⋮.

Template change

Clients and Projects each need the one extra "facts" cell, hidden on desktop, like History's. Tags only needs "entries" after the count.

Decided: the budget joins a project's facts line only when the project has one, labelled "Budget" in the same wording as the desktop column (3 hrs / mo, $3,500.00, 40 hrs). The label matters because a fixed fee otherwise sits next to the hourly rate as a second bare dollar figure.
