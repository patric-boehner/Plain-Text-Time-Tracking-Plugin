Visual style

Structure untouched — same screens, same columns, same flows. This is only about how it looks.

Three principles doing the work. The tool is plain text, so typography carries the design instead of chrome or colour. Descriptive, not evaluative, so nothing is red, nothing alarms, and colour names categories rather than passing judgment. Minimal friction, so the interface recedes and the content is the loudest thing on screen.

It still reads as WordPress — same blue for actions, same table and panel conventions, same admin furniture. The departures are a real type scale, warmer neutrals, lighter rules, and more room.

01

Type

Two families, one rule about which is which.

WordPress admin sets nearly everything at 13px, so hierarchy has to come from weight and colour alone. A real scale does that work instead. And the split between the families isn't decorative: monospace is what the clock measured or you typed; proportional is what the app inferred or you named. In any row you can see at a glance which half came from your own hands.

MONOSPACE — measured or typed

Times, durations, dates, money, record numbers, and the daily log itself. Tabular figures, so columns of numbers line up on the decimal without extra work.

PROPORTIONAL — inferred or named

Descriptions, client and project names, tags, labels, interface text. The parts a prediction produced, or that you gave a name to rather than measured.

02

Colour

Names things. Never judges them.

The current palette is saturated and reads as status lights — bright green, strong blue, vivid purple. That's a dashboard vocabulary, and it conflicts with a tool whose principle is to describe rather than evaluate. Desaturating them keeps every distinction while removing the implied verdict. Nothing is red anywhere in this app.

Billing models — categorical, equal weight
Hourly Monthly Fixed budget Internal Over allocation Development

Four models, four hues, none louder than another — because a fixed-fee project isn't better or worse than an hourly one. The fifth, over-allocation, is the only one carrying any warmth, and it's a muted ochre rather than orange: it's a fact about hours, not a warning.

Neutrals

Warmed a few degrees off WordPress's cold grey — #f4f3f1 rather than #f0f0f1. Barely perceptible side by side, but it makes a screen full of text read as paper rather than as a control panel, which suits a tool that's half notebook. Rules are lighter than WP's default so tables separate by rhythm rather than by lines.

The log is set as writing, not as a form field

Line height at 2.0, generous padding, no inner border, paper background flush with the panel. It's the only place in the app where you compose rather than review, and it should feel like a page rather than an input. Everything else on the screen is quieter than it is.

The @ and # hints are set as keys because they're literally keystrokes — the same reasoning as monospace for measured things.

What changed here is almost entirely spacing

Row padding from 10px to 15px, rules lightened, column headers set small and uppercase so they stop competing with the data underneath them. Day headers become a tinted band rather than a bordered panel of their own, which removes a border and a heading level from every day on the page.

Amounts and durations are tabular monospace, so the columns align on the digit without needing right-alignment tricks — and a column of aligned figures is far quicker to scan than a ragged one.

Over budget, without the verdict

The current page uses a bright orange for the overrun, which reads as an error condition. Here it's a muted ochre used consistently — the meter, the May bar, the stat qualifier — so it reads as one fact stated in one colour rather than as an alarm going off in three places.

This is the principle doing real work. The project went 249% over; that already happened and nothing on this screen can change it. Saying so plainly is descriptive. Saying so in red is a judgment about you.
